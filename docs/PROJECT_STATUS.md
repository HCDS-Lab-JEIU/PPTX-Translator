# 프로젝트 상태

## 구현·검증한 범위

번역 요청을 GUI의 페이지별 순차 호출에서 추출 문서 전체 기준으로 변경했습니다. 기본 60,000자의 서식 포함 JSON 예산 안에서는 페이지 수에 관계없이 한 번 요청하며, 초과 시에만 분할합니다. 일반 CLI 번역기의 기본 예산도 동일합니다. 잘못된 응답은 해당 항목만 한 번 재시도하고, 기존 체크포인트의 완료 항목은 재요청하지 않습니다. 한 요청에 묶은 경우 첫 응답을 받을 때까지 페이지 완료 수가 증가하지 않으며, 요청 도중 중지하면 응답을 저장하지 못한 묶음은 재개 시 다시 요청합니다.

모의 화면의 노드 설정 보존·공유 잔량·저장 이름·정지 중 UI 반응과, 페이지 체크포인트 재개 및 영어→한국어 적용을 자동 검증합니다. 현재 계정에서 Codex 모델/한도를 조회하고 임시 1장 PPT의 실제 번역→적용→PowerPoint/Codex 검토→저장 및 원본 보존을 확인했습니다. 로그인·로그아웃은 사용자 계정을 바꾸는 작업이므로 자동 테스트에서 실행하지 않았습니다.

남은 범위: 공식 Gemini CLI 설치 환경에서 실제 인증/모델 실행 검증, Gemini의 직접 로그아웃·정밀 계정 잔량·추론 옵션·이미지 검토 연동, 앱 재시작 후 작업 큐/체크포인트 가져오기, 한도 초기화 시 자동 재개, 별도 PC에서의 배포 검증입니다. 영상·이미지 속 글자 OCR은 하지 않습니다.

조정은 문서 전체를 먼저 렌더링하고 JPG 비교 모음을 일괄 검토해 후보 페이지를 고릅니다. 넘침 없이 한 줄이 두 줄로 늘어나는 경우도 PowerPoint의 실제 줄 수 비교로 후보에 포함합니다. 상세 검토는 후보 페이지만 묶어 요청하고 수정 페이지만 재렌더링합니다. 동일 입력·정책의 렌더링 및 완료 검토를 재사용합니다. 실제 회로해석법 47장의 렌더링 2회·JPG 비교 모음 12장·모의 전체 검토 요청 1회와 원본 보존을 확인했으며 유료 AI는 호출하지 않았습니다. 실제 AI를 사용한 전체 선별 정확도·압축문 의미 보존의 품질 비교는 남아 있습니다.

GUI에서 필요한 문장만 의미를 유지하며 압축하는 옵션을 켜고 끌 수 있습니다. 숫자·수식·단위·보호 표현·문단 경계·서식 구간을 검사하며 수식 XML은 재작성하지 않습니다. 압축문은 원래 문장과 비교해 후속 검토하고 결과에 `needs_review` 및 해당 페이지·도형·압축문을 기록합니다. 임의 문체 변경·용어 통일을 위한 전체 재작성은 지원하지 않습니다.

공식 참고: [Qt QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html), [Codex App Server 인증·모델·한도](https://learn.chatgpt.com/docs/app-server), [Gemini 인증](https://geminicli.com/docs/get-started/authentication/), [Gemini headless](https://geminicli.com/docs/cli/headless/), [Gemini 모델 선택](https://geminicli.com/docs/cli/model/).


## 문서·파일 정리

혼합 서식 번역은 원문의 서식 구간을 `[[STYLE_n]]…[[/STYLE_n]]`으로 모델에 전달하고, 번역된 의미 구간에 원본 run의 굵기·색상·기울임 등 서식을 적용합니다. 어순 변경 시 문자 위치로 서식을 배분하지 않습니다. 표시 누락·중복·중첩 및 문단·수식 경계 이동은 적용하지 않습니다. 의미 대응의 품질은 번역 모델에 의존하며 실제 문서 검토가 필요합니다.

GUI는 빈 응답·잘못된 JSON·누락/중복 ID·서식·숫자·수식·줄바꿈 검증 실패 시 문제가 있는 번역 항목만 한 번 재시도합니다. 계속 실패한 항목은 원문 XML을 유지하고 나머지 항목·페이지를 처리합니다. 텍스트 적용 중 검증 실패도 해당 텍스트와 편집 가능한 대체 표현을 복원한 뒤 진행합니다. 선택적 레이아웃 조정의 검증·렌더링·모델 실행 오류는 해당 페이지의 미검증 사본을 채택하지 않고 직전 결과를 유지합니다. 복구가 발생한 결과는 `needs_review`로 저장하며 최종 `.report.json`과 체크포인트에 원문 유지 항목·조정 실패 페이지를 기록합니다. 단위 테스트와 실제 회로해석법 자료의 모의 응답 검증은 유료 AI 호출을 하지 않습니다.

원본/추출 데이터 불일치·손상된 입력·출력 쓰기 실패·기존 결과 덮어쓰기 위험은 여전히 중단합니다. 사용자 중지·한도 일시정지는 복구로 무시하지 않습니다. 번역 도구의 인증·실행 오류도 중단하여 잘못된 연결로 전체 원문 결과를 생성하지 않습니다. 공용 번역기·적용 함수의 기본값은 엄격 검증이며 GUI가 `recover=True`를 사용합니다.

Windows에서 체크포인트 원자 교체가 일시적인 파일 잠금으로 거부되면 짧은 지연 후 최대 5회 재시도합니다. 기존 체크포인트를 지우지 않으며 권한 오류가 지속되면 중단합니다.

추출 스키마 3의 `texts.txt`는 일반 항목에 기존 JSON 문자열을 유지하고, 혼합 서식 항목에 `{"text": "원문", "styled_text": "서식 표시 포함 원문"}` 객체를 사용합니다. `content.json`의 `text`는 표시 없는 원문이며, 수식 내부 텍스트는 별도 항목으로 유지합니다.

- GUI 진입점은 `app.py`입니다.
- GUI가 사용하지 않는 기존 파이프라인 CLI와 근사 복원 도구를 `legacy/`로 분리했습니다.
- 공용 처리 모듈과 `pptx_pipeline/`는 GUI에서도 사용하므로 활성 코드로 유지합니다.
- README는 사용자용 빠른 시작, 개발 규칙은 `AGENTS.md`, 상세 문서는 `docs/`로 구분합니다.
- 기존 검증 결과는 구현 당시의 기록이며, 각 PC의 설치·계정·모델 지원은 실행 시 다시 조회합니다.

## Windows 패키징

`packaging/windows/`에 PyInstaller spec, 격리 빌드 스크립트와 EXE 전용 진입점을 분리했습니다. Python 런타임을 포함한 폴더·ZIP 배포를 사용합니다. AI CLI와 PowerPoint는 별도 설치 항목입니다. 설치 프로그램·자동 업데이트·코드 서명은 미구현입니다.

`v0.2.0-alpha`의 Windows x64 빌드와 약 59MiB ZIP 생성을 확인했습니다. PATH에 Python이 없는 상태의 EXE 데모 실행·종료, 렌더러 및 신규 선별·압축·캐시 모듈 포함, ZIP CRC·배포 폴더와의 일치·개인 자료 제외를 확인했습니다. 격리 빌드 환경에서 회귀 테스트 105개가 통과했습니다. 배포 ZIP의 SHA256 파일을 함께 제공합니다. Python이 설치되지 않은 별도 PC의 실제 번역·조정 검증은 남아 있습니다.
