# 프로젝트 상태

## 구현·검증한 범위

영어 번역에서 단순 한글/영문 용어 병기 항목은 기존 영문을 재사용하고 모델 요청에서 제외합니다. 문장 속 병기는 기존 영문을 한 번만 쓰도록 지시하고, 원문에 있는 영문 표현이 응답에서 정확히 중복된 괄호를 제거합니다. 다른 언어·조건·단위·변수·숫자·수식은 보수적으로 구분하며 영문 서식을 유지합니다. 기존 결과 파일이나 완료한 번역 체크포인트를 일괄 변경하지는 않습니다.

PDF 조정 진입 시 `ModuleNotFoundError`가 난 환경을 조사해, 앱 패키지가 설치된 Conda 환경과 기존 빌드 환경에 새 의존성 `pypdfium2`가 빠져 있던 차이를 수정했습니다. PowerPoint를 열기 전에 PDF 의존성을 확인하고, GUI 로그·보고서에 누락 모듈명을 남깁니다. Windows 빌드는 설치 생략 여부와 관계없이 Python/native PDF 렌더링을 사전 검사하고 PDF 모듈을 명시적으로 수집합니다. 의존성 누락 시 검증된 번역본은 계속 보존합니다. 회귀 테스트 142개와 빌드 환경의 실제 47장 PDF 처리 흐름을 확인했습니다.

GUI 조정의 첫 작업을 전체 슬라이드 단일 PDF 출력으로 변경했습니다. PDF 전체를 읽어 페이지별 `font/spacing/images/compression` 중 필요한 종류를 복수로 예측한 뒤 해당 단계에만 보냅니다. 숨긴 슬라이드도 포함해 PDF 페이지 번호를 유지하며, PDF·예측·단계별 검토를 체크포인트에 보존합니다. 이미지 입력 도구는 PDF에서 렌더링한 비교 이미지를 일괄 검토합니다. 회로해석법 실제 47장의 단일 PDF·전 페이지 읽기·모의 일괄 예측 1회·원본 해시 보존과 숨긴 페이지가 포함된 3장 자료의 PDF 번호·텍스트를 확인했습니다. 전체 회귀 테스트 141개와 GUI 데모를 확인했습니다. 모의 응답으로 조정 전 일괄 예측·복수 유형 분기·관련 없는 단계 생략·부분 조정 범위·캐시 및 예측 실패를 검증합니다. 유료 모델을 호출한 예측 정확도·토큰·속도 비교는 아직 수행하지 않았습니다.

GUI 조정을 폰트 크기→공백·간격→그림 크기·위치→문장 간소화의 단계별 파이프라인으로 변경했습니다. 수정 사본을 재렌더링하고 해결된 페이지를 확인한 뒤 후보에서 제외합니다. 미해결·검토 실패 페이지는 다음 단계로 넘기고, 수정 대상이 없는 단계는 생략합니다. 기본 수정 횟수는 단계당 1회이며 문장 간소화 비활성화 시 마지막 단계를 요청하지 않습니다. 모델 응답과 실제 적용 모두 단계별 작업 종류를 제한합니다. 공백 변경은 단어·수치·수식·명시적 줄 경계와 비어 있지 않은 문단 서식을 보호합니다. 단계별 후보·해결·잔여 페이지와 캐시를 기록하며, 모의 응답으로 순서·후보 제거·실패·재개를 검증했습니다. 실제 모델의 단계별 해결률·시간·토큰 비교는 아직 측정하지 않았습니다.

전기회로소자 11페이지의 번역문이 XML에는 있지만 PowerPoint에서 보이지 않던 회귀 오류를 수정했습니다. 문단 재구성 시 `a:endParaRPr` 뒤에 새 텍스트를 넣던 것이 원인이며, 모든 텍스트를 문단 끝 서식 앞에 삽입하고 적용 후 순서를 검사합니다. 이전 적용 버전의 체크포인트는 저장된 번역을 원본에 다시 적용하므로 재번역 호출 없이 복원할 수 있습니다. 실제 저장 번역으로 35장·248개 텍스트 프레임의 문단 순서를 확인했고, 11페이지 수정 전후를 PowerPoint로 렌더링해 본문 표시 복원을 확인했습니다. 복구 사본은 새 경로에 저장하며 번역 확장에 따른 배치는 별도 검토가 필요합니다.

선택적 조정의 예상하지 못한 예외·임시 파일 접근 오류는 검토 필요로 기록하고 검증된 번역본 저장을 계속합니다. 조정 후보의 적용·재렌더링 실패는 그 사본만 버리고 앞서 검증된 결과를 유지합니다. 로그·보고서에 발생 단계·예외 종류를 기록하고 데이터 처리 오류의 설명은 민감값을 가린 뒤 기록합니다. 인증/RPC 원문은 기록하지 않습니다. 사용자 중지·한도 대기·자원 고갈과 필수 최종 저장 실패는 별도로 처리합니다.

`p:contentPart`가 포함된 자료를 읽을 때 일반 lxml 요소를 python-pptx 도형으로 잘못 래핑해 `has_ph_elm` 또는 그룹 내부 `rot` 속성 오류가 발생하던 경로를 수정했습니다. 미지원 개체는 원본 보존하고, 호환 그림/도형이 있으면 사용하며 나머지 추출·번역·조정을 계속합니다. 페이지별 보존 목록과 경고를 남기고 결과는 검토 필요로 표시합니다. 직접 삽입·호환 분기·그룹 내부와 번역/조정 후 XML 구조·외부 ZIP 부품 보존을 모의 자료로 검증합니다. 추가 제공된 `01_Class Overview_` 실제 원본 22장도 삽입 개체 5개를 보존하며 추출·원문 적용 저장에 성공했습니다. 제공된 01~06 자료 모두 원문 적용 결과와 원본의 해시가 일치했으며 유료 모델은 호출하지 않았습니다.

번역 요청을 GUI의 페이지별 순차 호출에서 추출 문서 전체 기준으로 변경했습니다. 기본 60,000자의 서식 포함 JSON 예산 안에서는 페이지 수에 관계없이 한 번 요청하며, 초과 시에만 분할합니다. 일반 CLI 번역기의 기본 예산도 동일합니다. 잘못된 응답은 해당 항목만 한 번 재시도하고, 기존 체크포인트의 완료 항목은 재요청하지 않습니다. 한 요청에 묶은 경우 첫 응답을 받을 때까지 페이지 완료 수가 증가하지 않으며, 요청 도중 중지하면 응답을 저장하지 못한 묶음은 재개 시 다시 요청합니다.

모의 화면의 노드 설정 보존·공유 잔량·저장 이름·정지 중 UI 반응과, 페이지 체크포인트 재개 및 영어→한국어 적용을 자동 검증합니다. 현재 계정에서 Codex 모델/한도를 조회하고 임시 1장 PPT의 실제 번역→적용→PowerPoint/Codex 검토→저장 및 원본 보존을 확인했습니다. 로그인·로그아웃은 사용자 계정을 바꾸는 작업이므로 자동 테스트에서 실행하지 않았습니다.

남은 범위: 공식 Gemini CLI 설치 환경에서 실제 인증/모델 실행 검증, Gemini의 직접 로그아웃·정밀 계정 잔량·추론 옵션·이미지 검토 연동, 앱 재시작 후 작업 큐/체크포인트 가져오기, 한도 초기화 시 자동 재개, 별도 PC에서의 배포 검증입니다. 영상·이미지 속 글자 OCR은 하지 않습니다.

조정은 문서 전체를 먼저 렌더링하고 JPG 비교 모음을 일괄 검토해 후보 페이지를 고릅니다. 줄 수 증가·측정 누락·미리보기 불확실성만으로 후보에 넣지 않습니다. 자동 후보는 허용 오차를 초과하는 새 넘침으로 제한하고, 시각 후보는 겹침·잘림·넘침·읽을 수 없음의 구체적 근거를 요구합니다. 전체 선별이 실패해도 모든 페이지를 상세 조정하지 않고 명확한 넘침만 처리하며 나머지는 미검토로 기록합니다. 변경한 선별 규칙 버전으로 과거의 과도한 후보 캐시는 재사용하지 않습니다. 동일 입력·정책의 렌더링 및 완료 검토는 재사용합니다. 실제 회로해석법 47장의 렌더링 2회·JPG 비교 모음 12장·모의 전체 검토 요청 1회와 원본 보존을 확인했으며 유료 AI는 호출하지 않았습니다. 실제 AI를 사용한 전체 선별 정확도·압축문 의미 보존의 품질 비교는 남아 있습니다.

GUI에서 필요한 문장만 의미를 유지하며 압축하는 옵션을 켜고 끌 수 있습니다. 숫자·수식·단위·보호 표현·문단 경계·서식 구간을 검사하며 수식 XML은 재작성하지 않습니다. 압축문은 원래 문장과 비교해 후속 검토하고 결과에 `needs_review` 및 해당 페이지·도형·압축문을 기록합니다. 임의 문체 변경·용어 통일을 위한 전체 재작성은 지원하지 않습니다.

## 문서·파일 정리

혼합 서식 번역은 원문의 서식 구간을 `[[STYLE_n]]…[[/STYLE_n]]`으로 모델에 전달하고, 가능한 경우 번역된 의미 구간에 원본 run 서식을 적용합니다. GUI에서는 번역상 사라지는 조사·짧은 구간 때문에 전체 번역을 거부하지 않습니다. 알려진 비중첩 구간은 일부 누락돼도 사용하고, 대응할 수 없는 표시는 제거해 번역문을 기본 서식으로 적용합니다. 의미별 대응이 없을 때 번역 문자 위치로 강조를 배분하지 않습니다. 서식과 줄바꿈 복구 내역을 별도로 보고하며, 의미 대응의 품질은 모델과 최종 검토에 의존합니다. 공용 함수의 기본 엄격 검증 모드는 유지합니다.

GUI는 서식·일반 줄바꿈 문제를 재번역하지 않고 번역을 유지합니다. 수식의 순서·개수가 같고 줄바꿈만 다르면 원래 수식 위치에 맞춰 복원합니다. 빈 응답·잘못된 JSON·누락/중복 ID·숫자·수식 표시 불일치는 해당 항목만 구체적인 실패 사유를 주어 한 번 재시도합니다. 계속 실패한 내용은 원문 XML을 유지하고 사유별 개수를 로그와 보고서에 기록합니다. 이전 체크포인트의 실패 항목만 새 규칙으로 재시도하며 성공한 번역과 과거 실패 이력은 유지합니다. 텍스트 적용 중 복구 불가능한 오류는 해당 텍스트와 대체 표현을 복원한 뒤 진행합니다. 미번역·조정 실패·압축·미검토는 `needs_review`로 저장하고, 단순 서식 복구는 별도 기록합니다. 서식 복구만으로 상세 조정을 강제하지 않습니다.

회로해석법의 저장된 정상 번역에서 모든 서식 표시와 줄바꿈을 제거해 모의 재생한 검증에서 47장·71개 서식 복구 항목을 재요청 없이 처리했고 번역 실패·원문 유지가 없었습니다. 수식 XML은 기존 정상 번역과 일치했습니다. 이전 실행에서 44장이 후보였던 자료의 동일 렌더링 측정을 새 기준으로 다시 계산하면 측정상 필수 후보는 6장입니다. 이 수치는 모델을 다시 호출한 최종 시각 선별 결과가 아니며, 명확한 추가 시각 결함이 있으면 후보가 늘 수 있습니다. 이 검증은 유료 AI 호출을 하지 않았습니다.

원본/추출 데이터 불일치·손상된 입력·출력 쓰기 실패·기존 결과 덮어쓰기 위험은 여전히 중단합니다. 사용자 중지·한도 일시정지는 복구로 무시하지 않습니다. 번역 도구의 인증·실행 오류도 중단하여 잘못된 연결로 전체 원문 결과를 생성하지 않습니다. 공용 번역기·적용 함수의 기본값은 엄격 검증이며 GUI가 `recover=True`를 사용합니다.

Windows에서 체크포인트 원자 교체가 일시적인 파일 잠금으로 거부되면 짧은 지연 후 최대 5회 재시도합니다. 기존 체크포인트를 지우지 않으며 권한 오류가 지속되면 중단합니다.

추출 스키마 3의 `texts.txt`는 일반 항목에 기존 JSON 문자열을 유지하고, 혼합 서식 항목에 `{"text": "원문", "styled_text": "서식 표시 포함 원문"}` 객체를 사용합니다. `content.json`의 `text`는 표시 없는 원문이며, 수식 내부 텍스트는 별도 항목으로 유지합니다.

- GUI 진입점은 `app.py`입니다.
- GUI가 사용하지 않는 기존 파이프라인 CLI와 근사 복원 도구를 `legacy/`로 분리했습니다.
- 공용 처리 모듈과 `pptx_pipeline/`는 GUI에서도 사용하므로 활성 코드로 유지합니다.
- README는 사용자용 빠른 시작, 개발 규칙은 `AGENTS.md`, 상세 문서는 `docs/`로 구분합니다.
- 기존 검증 결과는 구현 당시의 기록이며, 각 PC의 설치·계정·모델 지원은 실행 시 다시 조회합니다.

## Windows 패키징

완료 목록과 실행 종료 로그에 추가 검토가 필요한 슬라이드 번호를 표시합니다. 기존 번역·적용·조정 판정을 모아 결과 `.report.json`의 `review_required_pages`에 저장하며 추가 AI 호출은 하지 않습니다. 단순 서식 복구만 있는 페이지는 검토 목록에 추가하지 않습니다.

`packaging/windows/`에 PyInstaller spec, 격리 빌드 스크립트와 EXE 전용 진입점을 분리했습니다. Python 런타임을 포함한 폴더·ZIP 배포를 사용합니다. AI CLI와 PowerPoint는 별도 설치 항목입니다. 설치 프로그램·자동 업데이트·코드 서명은 미구현입니다.

`v0.3.0-alpha`의 Windows x64 빌드와 약 63MiB ZIP 생성을 확인했습니다. PATH에 Python이 없는 상태의 EXE 데모 실행·종료, PDF 전체 예측·단계별 조정·영문 병기 재사용 모듈 포함과 번들 PDFium DLL의 실제 문서 생성·종료, ZIP CRC·배포 폴더와의 일치·개인 자료 제외를 확인했습니다. 격리 빌드 환경에서 회귀 테스트 150개가 통과했습니다. 배포 ZIP의 SHA256 파일을 함께 제공합니다. Python이 설치되지 않은 별도 PC의 실제 번역·조정 검증은 남아 있습니다.
